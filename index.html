The premium layer · formal verification

      
We can prove the process, not just the snapshot.

      
Every check above reads your evidence — was that access revoked in time? The premium layer proves the machine that produces the evidence: does your revocation pipeline always eventually revoke, across every possible sequence of events? No point-in-time audit can answer that — only model-checking can.

      

        

          
The requirement, in English

          
Protect CUI during and after personnel actions — when someone is terminated, their access must not linger.

          
A snapshot asks “was it revoked in time?” It cannot ask whether it always will be.

        

        

          
The model, in TLA+ — excerpt from the real spec

          
\* obligation: a terminated user is eventually revoked
Liveness == terminated ~> revoked

\* the worker revokes, but only while it is up
WorkerRevoke == queued /\ workerUp /\ revoked' = TRUE

\* it can crash before it acts -- what starves it
Crash == workerUp /\ ~revoked /\ workerUp' = FALSE

\* holds ONLY under strong fairness
Spec == Init /\ [][Next]_vars /\ SF_vars(WorkerRevoke)

        

      

      
Point the model checker at that spec and it explores every reachable behavior:

The model checker explored every reachable behavior. No failure exists — the obligation terminated ↝ revoked holds in every one.

FAILS

          
It returns a concrete counterexample: a crash-loop where the account stays live forever — while every snapshot the assessor sees still shows green.

          
terminated  ->  queued
   worker crashes   <-.
   worker restarts  --'   (never revokes)
=>  obligation VIOLATED

        

      

      
This is genuine formal verification (model-checking) — a harder guarantee than the checks above, and the reason a formal-methods specialist is in the room. The entry tier checks your evidence; this proves the process behind it. Re-runnable from the actual spec on request.
